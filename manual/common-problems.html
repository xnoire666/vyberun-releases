Common problems

The problems people run into most, and how to fix them.

"Windows protected your PC"

The zip version isn't signed, so Windows warns the first time it starts. Choose More info, then Run anyway. If Smart App Control blocks it with no way to run it, install vyberun from the Microsoft Store instead: that version is signed by Microsoft. See Installing.

vyberun doesn't start: .NET is missing

The zip version needs the .NET 10 Desktop Runtime (x64). Windows offers the download when it's missing; you can also get it from Microsoft's .NET page. The Store version includes it.

My tabs are gone

Tabs survive closing vyberun, but not everything. Check which one happened:

  • Windows restarted, shut down or signed you out. That ends every program, including your tabs. Cards, spaces and servers are kept; open new tabs on them.
  • vyberun was closed with Stop everything, or Settings ▸ Closing vyberun is set to stop them.
  • You started a different copy of vyberun. Each vyberun folder keeps its own tabs. If you unzipped a new version into a new folder, the old folder's vyberun still has the tabs: start that one, and next time unzip over the old folder.
  • The Store updated vyberun. An update ends running tabs.

Logs shows how to tell from the logs.

Claude Code doesn't see vyberun's tools

Claude Code loads its tools when it starts. A Claude started before vyberun set up its tools, or before an update, doesn't have them yet. Quit it (/exit) and start it again in the same tab, for example with claude --continue to keep the conversation.

Claude Code says "hook failed"

Claude Code runs vyberun's hooks at the start of every session and with every message, in any terminal. If they can't run, it shows a red "SessionStart hook failed" or "UserPromptSubmit hook failed". The usual reasons:

  • vyberun was uninstalled, but its setup for Claude Code is still there. Take it out as Uninstalling describes.
  • The Store version 0.1.10. Its tools for Claude couldn't start. Update to 0.1.11 or later: it repairs the setup by itself when it starts, or open the checklist and choose Fix.

The checklist (Settings ▸ Claude Code ▸ Open the checklist…) says whether vyberun's tools start, and if not, why.

vyberun closes while Claude reads a tab

Before 0.1.11, vyberun could close by itself while Claude read another tab with nothing highlighted in it. Update vyberun. Your tabs keep running meanwhile: open vyberun again and they're back.

Claude says "vyberun isn't answering"

Claude's vyberun tools work only while vyberun is open. vyberun was closed, restarting, or had stopped. Open vyberun, then ask Claude again. If it happens while vyberun is open, see Reporting a problem.

A Claude tab ignores the mouse

If you can't scroll or select in a Claude Code tab, that Claude is probably running as a background session (Claude Code's Agent View), which takes over the mouse. Stop it with claude stop <its short id>, then claude --resume. Setting "disableAgentView": true in Claude Code's settings avoids it.

My typing goes to the wrong place

A split pane may have opened by accident: Ctrl+Shift+W, A, S or D splits the tab, and the new pane takes the keyboard. Click the pane you want, or close the new one with Ctrl+Shift+Q.

A setting I changed in a file came back

vyberun writes all its settings back on the next change, so an edit made in its files while it runs is lost. Change the setting in vyberun, or edit the file with vyberun closed. See Files vyberun uses.

Git Bash or Ubuntu isn't offered

The shell list shows what's installed. Install Git for Windows for Git Bash, or WSL with Ubuntu (wsl --install in an administrator PowerShell) for Ubuntu tabs, then restart vyberun.

Copying files to a server stops with "Cannot answer interactive prompts"

The copy asked a question it can't answer, usually "login as:" (a saved PuTTY session without a user name) or a key's passphrase. Add the user name in the server's settings, or use a key without a passphrase (or load it into Pageant first).
